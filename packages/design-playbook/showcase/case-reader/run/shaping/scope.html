DESIGN-PLAYBOOK / 同一次需求的完整本地运行 / 范围确认

读到真正的案例，
也读懂它能证明什么。

新建一个离线、只读的案例阅读入口。目录按需求、方向、验收、接续、交付组织；正文直接显示本仓原始材料和来源，不再跳到模拟队列操作。

这一步只确认需求范围。下一步会单独展示设计方向；实现后才会真实取证、评审和生成交付包。不会把你的范围确认当作实现通过。

CP-A · 目标与成功标准

  1. 目标：团队在一个入口按旅程查看真实案例原文，明确每份材料的证据边界。
  2. 使用者：工程师、产品 / 设计协作者和评审者。
  3. 成功标准：逐项原文一致；搜索与无结果恢复；链接直达 / 刷新 / 历史恢复；三种视口与键盘可用；离线交付仍可读且原文不会被执行。
  4. 不做：不增加后端、账号、遥测、第三方依赖；不运行材料中的命令；不修改历史记录。

CP-B · 主路径

采用单页目录 + 原文：选择材料 → 核对归属和边界 → 读原文；窄屏上下排列。相比新开多个 Markdown 页面，这条路径保留旅程上下文。

CP-C · 假设与执行档位

  • 场景假设：用于团队分享后的自助阅读，先覆盖现有材料。
  • 权限边界：只读；新增依赖、对外发布或扩大范围需另行询问。
  • 档位：路由器返回 P2 标准，完整执行规格、设计、实现与评审；不是省略流程的点修。
  • 仅本次开启全部审计：工艺检查 + 真实运行取证 + 验收。

请在外层反馈中确认上述 CP-A / CP-B / CP-C，或点明要修改的项目。若认可，可写“按以上范围执行”后确认；请不要确认尚未实现的功能已经通过。

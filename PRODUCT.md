# Product

## Register

product

## Users

Designers, product managers, and engineers using coding agents to define,
implement, review, and hand off product UI work. They need to understand what
was decided, what was observed, what remains blocked, and which source owns the
next action without reconstructing an agent run from raw artifacts.

## Product Purpose

design-playbook provides Design I/O for coding agents: declarations define what
good means, contracts control how work enters the pipeline, and criterion-bound
evidence plus point-back recirculation keep implementation reviewable. Success
means UI work is constrained, traceable, proportionate to risk, and able to
return failures to the declaration that owns them.

## Brand Personality

Precise, calm, and accountable. The product should feel like a focused working
instrument: candid about uncertainty, restrained in presentation, and confident
because claims are visibly connected to sources.

## Anti-references

- Marketing-style SaaS pages that turn operational status into a hero section.
- Decorative card grids, glass surfaces, gradients, oversized metrics, and
  ornamental motion that compete with evidence and decisions.
- Generic reporting dashboards that hide source ownership behind aggregate
  scores or imply a new verdict.
- Interfaces that collapse agent judgment, user confirmation, and runtime
  Evidence into one undifferentiated status.
- Dense engineering logs presented directly to product stakeholders.

## Design Principles

1. Lead with disposition and the next owning action.
2. Keep every important claim traceable to its authoritative source.
3. Separate requirements, decisions, observations, and verdicts visibly.
4. Make uncertainty and blocked states explicit instead of smoothing them over.
5. Keep workflow surfaces quiet, scannable, and proportional to the task.

## Accessibility & Inclusion

Target WCAG 2.2 AA for product-facing surfaces. Preserve semantic structure,
keyboard access, visible focus, sufficient text and state contrast, zoom and
narrow-screen reflow, non-color status cues, and readable print output. Motion
must be nonessential and respect reduced-motion preferences; static handoffs
should not require motion or JavaScript at all.

# CONTEXT — design-playbook

Domain glossary and product facts for agents. Updated by `/grill-with-docs` / `/domain-modeling`.

## Product

**design-playbook** — Claude Code / Codex **plugin for evidence-backed UI delivery**. It runs **Design I/O**: declarations + contracts so UI generation is constrained, reviewable, provable, and recirculatable.

No reading-demo app in-repo (removed). Product surface is the installable package only.

## Glossary

> Evidence exists only to satisfy a declared criterion.
> Providers never produce evidence directly; they produce artifacts that become evidence only when bound by a manifest to a criterion.

| Term | Meaning | Avoid |
| --- | --- | --- |
| **Design I/O** | Pipeline: `design-baseline? → reference-intake? → ux-spec? → plan? → (native-craft?) → ui-picker → (preview*) → fill → craft-guard → (observe*) → ui-evaluator` | “just prompt better” |
| **design-baseline** | Conditional existing-product initialization (ADR-0012): deep module `prepare`/`confirm`/`verify` with `state.json` gate; discover/validate project `DESIGN.md`; missing/stale → provenance-backed draft + explicit confirmation before durable write/Fill | generic style pack; silent overwrite; forgeable confirm files; third-party reference authority |
| **reference-intake** | Conditional declaration input (ADR-0011): screenshot/URL/design/product analogy → run-local `reference/contract.md` + `manifest.json` with observed/inferred + Keep/Change/Do not copy; not a gate | style library; visual Pass/Fail; Fill from reference assets |
| **Declaration** | What good is: spec, domain, craft, design, components, template | “guidelines”, “vibes” |
| **Contract** | How work enters the pipeline: skill timing, evaluator acceptance | “prompt pack” alone |
| **Interactive requirement shaping** | Human-in-the-loop process that turns a vague UI ask into confirmed product intent and a run-scoped UX spec while preserving assumptions, open decisions, and confirmation authority. Session artifacts (question queue, assumption batches, confirmation batches) are the shaping-process authority with an alive→archived→discardable lifecycle, and reopening always starts a new session. The contract remains the sole persistent decision authority: sessions project into it and have no bypass write channel | a one-shot PRD prompt; a third specification SSOT |
| **First-party UI/UX capability matrix** | Product-owned map of eight confirmed capability domains: interactive requirement shaping, interaction modeling, tool-neutral design decisions, dual-track implementation review, evidence binding, point-back recirculation, rule governance, and cross-run learning. External reference material is benchmark input only; it does not become a runtime dependency or rule authority | an integration catalog; copied third-party checklists |
| **Dual-track review** | Implementation review runs a product track (per-L6 supported/unsupported/unverifiable), an interaction track, and a cross-cutting applicability matrix; severity (S3/S2/S1) and disposition (blocking/advisory/info) are separate axes — fact-class S3 may block, judgment-class S3 never blocks without user escalation, and an implemented-UI pass requires at least one bound rendered or interaction artifact | collapsing severity and disposition into one field; agent judgment standing in for user evidence; a pass with no bound runtime artifact |
| **First-party rule registry** | Product-level read-only declaration (`rules.md`, G8-self-validated) unifying every review rule: stable family-serial IDs, authority level orthogonal to enforcement status (draft/advisory/machine-enforced/deprecated), three-state applicability predicates (applicable / not-applicable with reason / blocked), breaking revisions fork a new ID via supersedes; promotion to machine-enforced and its exemption are user-only decisions in the append-only governance log | rules scattered across skills/validators; silent N/A-style skips; agent-self-promoted gates; external samples as rule authority |
| **Contract state** | Every persistent contract field is explicitly `decided`, `assumed`, or `open`. Only explicit user confirmation creates `decided`; `assumed` must be acknowledged per run and `open` blocks dependent work. Bind-first resurfaces the latter two and source/schema drift requires review | omitted status as an implicit default; agent self-promotion; calendar-only expiry |
| **Persistent contract v1** | One project-level contract bound as a whole into a run. Run exceptions are explicit decisions that stay local or are promoted after user confirmation. Layered inheritance is deferred until repeated scoped overrides provide evidence for real precedence boundaries | project/page/component inheritance; deep merge; speculative override hooks |
| **Decision log** | Append-only `decisions.jsonl` beside the persistent contract: stable decision ID, field path, choice, rationale, supersession, and confirmation time. Written only after explicit user confirmation; the run ledger binds its SHA | decisions embedded in agent-rewritable `spec.md`; accepting a whole spec as blanket approval; a tamper-proof claim |
| **Closed-loop run** | One Design I/O run that declares the outcome, proves each success criterion, points failures back to their owning declaration, recirculates blocking findings within a bounded retry policy, and stops with an explicit verdict | “generated a page” / “looks done” |
| **Static run handoff** | Optional one-off, read-only projection between design completion and real implementation. It lets an implementation recipient understand the request, key design decisions, criterion-organized evidence summary, limitations, and source verdict offline. It is a delivery artifact, never an in-design review surface, reusable reporting capability, evidence authority, or source of truth | invited human review; shareable run report; PWA; dashboard; exporter; evidence |
| **Confirmation source** | Where a delivery credential's `confirmed` came from. Only the durable `confirm-round-*.json` that `transaction.py` wrote can substantiate it (`confirm-record`); anything else is `unsubstantiated` and fails closed with a stated reason. A choice label, a live review session, or the builder's own reasoning is never authority — the credential is built from run artifacts and outlives every review round | re-deriving `confirmed` from a label; inferring it from a running server; a `Pass` with no record behind it |
| **Not-applicable gate** | The fourth gate state, beside pass/fail/pending, for a conditional gate whose precondition never occurred. It is excluded from `gatesPassed` and is not a fail; delivery is judged by every gate being `pass` or `not-applicable`, never by an "8/8" count. Preconditions are sampled before any artifact is written, so a builder cannot manufacture its own | counting an untriggered gate as passed; "8/8" as the acceptance signal; a builder testing a directory it writes into |
| **Hallmark tokens** | The Preview control shell's CSS custom-property contract: every colour, radius, and shadow resolves from a token declared in one of the two theme blocks at the top of `control.css`, so a theme swap needs no rule edits. The sandboxed prototype iframe cannot read parent custom properties, so the bridge inlines the light-theme literals and a lockstep test keeps the two in step | inline colours outside the theme blocks; a second palette in the bridge; per-component overrides |
| **Invited human review** | Optional in-design review loop where invited people inspect a current design candidate and return comments or anchored annotations before design work is finalized. A protected invitation may control access, but reviewer feedback remains separate review input that re-enters the design loop; it never directly mutates authoritative run artifacts, evidence, decisions, or verdicts | Static run handoff; implementation handoff; source editing; reviewer feedback as automatic approval |
| **Run contract** | The five controls fixed before execution: Goal, Success, Evidence, Stop, Confirm | an open-ended task list |
| **Tiered run profile** | Every run is graded P1 point-fix / P2 standard / P3 full by declaration-touch surface (which decided fields, criteria, or E-tier design triggers it revises); `run_profile.py route` proposes the initial grade from RequestFacts, the user confirms it once per run, promotion is automatic while demotion is user-only, and process weight scales with change consequence. The tier lives in a mandatory `run-profile` block at the top of `plan.md`; structural gates (G1-G12) are never waivable — only rule hits carry exemptions | uniform-weight runs for one-line fixes; skipping the tier block; waiving structural gates; a second intent table in skill prose |
| **audit-preferences** | User-selectable switches for the three audit/acceptance stages (`craft-guard`, `observe*`, `ui-evaluator`) with repository-level defaults in `.design-playbook/preferences.yaml` (+ personal `preferences.local.yaml` override) and per-run declaration overriding them (ADR-0033). Fill and preview confirmation stay unskippable; every skip is recorded with a reason in the run-profile skip list, and a skipped `ui-evaluator` still yields a skeleton `point-back.md` marked `audited: false` | silent stage skips; preferences as routing input; an unmarked skipped run reading as audited |
| **No-run disposition** | Entry outcome for an answer, review, diagnosis, or non-durable plan that does not create a Design I/O run or `.scratch/<run>/` artifacts. A supplied image may be inspected directly when the host supports vision; otherwise the response uses text/file facts and states the limitation once; when only an image is supplied without text, it first asks the user for a short written description before continuing | answer-only; quick path; simplified run |
| **Reference source storage** | Observable retention form for a reference source: `copied`, `linked`, `remote`, or `symbolic`. A temporary image that enters a Design I/O run is copied and hashed under the run-local reference tree; storage never grants Fill authority | lifecycle; provider-specific input type; reference asset as Fill source |
| **L6 criterion** | One independent user-visible risk or outcome, expressed as Given/When/Then. Three to seven top-level criteria is a soft authoring budget; proof modalities such as accessibility, runtime capture, or multiple stacks attach to the same criterion unless they represent independently blocking outcomes | one criterion per tool, screenshot, stack, or evidence type; a hard count cap that hides real risk |
| **Evidence ledger** | Criterion-shaped acceptance record: required proof, observed proof, and pass/fail/blocked/N/A result for every success criterion | an unstructured review summary |
| **Evidence** | Criterion-addressable artifact: a runtime capture bound by a manifest to an L6.<n>; no criterion → telemetry, not evidence | "observation", "screenshot", an unbound artifact |
| **Recirculate** | Send a failure back to the owning declaration, then resume | blind whole-page restyle |
| **Point-back** | Evaluator finding names `source` declaration + `fix` | “looks off”, “polish more” |
| **Decision report** | ui-picker output before code: scene, template, components, risks, plus versioned design-decision entry blocks; exploration is tiered to consequence — record (R, direct entry), compare (C, in-baseline candidates with agent-recorded trade-offs), explore (E, identity/composition-level directions user-confirmed) — and in-baseline choices never trigger full exploration; providers are replaceable data-contract adapters (candidate descriptors only) whose assets are path+hash references, never bound evidence | coding from intuition |
| **Anti-default check** | Compare/explore-tier self-check in ui-picker step 4 — "is this the direction I would produce for any similar brief?" — answered against the DD entry; advisory review rule, judgment-class, never blocking | a blocklist of specific styles as authority; firing on record-tier single choices; a blocking gate |
| **Memorable element** | The one thing an explore-tier direction is remembered by; an E-tier DD entry names it in its rationale. Prose expectation only — no machine-checked field | a mandatory top-block field; required memorable elements on P1/P2 runs; boldness spread across every element |
| **plan (step)** | Orchestrator-only handoff (`.scratch/<run>/plan.md`): run scope pointers, description→spec map, ui-picker input pack; not a run-contract control and not a machine gate | host Plan Mode; pre-written decision report |
| **preview*** | Optional disposable HTML prototype loop via external MCP tool `preview_prototype`; skip when adapter absent | fill from prototype files; ui-picker step 5 |
| **Preview integrity** | Shared, read-only rules over Preview artifacts: LF-normalized prototype digest, feedback floor, current-round discovery, and confirm validity. Bundled Preview runtime owns these rules; transaction still owns decision authority/persistence, while G5 and run status own host-specific diagnostics and presentation | a second confirmation authority; artifact writing; G5-specific findings; status narration |
| **observe*** | Optional post-Fill runtime-evidence loop via external MCP tool `execute_capture_plan`; provider produces artifacts, orchestrator binds them to L6 criteria via manifest; skip when provider absent | building a runtime/dev server; provider writing the manifest |
| **Capture Plan** | Derived, disposable: L6 Given/When → state+actions, Then → required; never a SSOT, never edited for intent; L6 wins on conflict | a standalone test script; a persisted plan file |
| **Capture contract v1** | Atomic versioned seam for `observe*`: `schemaVersion: 1`, explicit viewport (width/height/DPR/color scheme), and deterministic freeze. The orchestrator snapshots the full request in the manifest; missing/unknown versions fail closed and legacy run-local evidence is recaptured | hard-coded provider viewport; partial rollout; dual-read legacy compatibility |
| **Manifest** | Execution-record SSOT (`.scratch/<run>/evidence/manifest.jsonl`, append-only): self-contained entries binding criterion ↔ artifact; the only seam between Contract and Runtime objects | provider output; an editable log |
| **Provider** | Runtime executor of a capture plan; produces artifacts, never evidence; probed via `tools/list` for `execute_capture_plan`; Playwright MCP / manual / future | collector; judge; a criterion-aware tool |
| **G5** | Conditional `validate_run.py` gate: if preview occurred, require `confirm-round-*.json` with `confirmed=true` and matching `report_ref` | always-on preview gate; scanning Fill source for confirm refs |
| **G6** | Conditional `validate_run.py` gate: if a ledger `observed` references an `evidence/` artifact, require the artifact to exist and a manifest entry to bind it to the matching L6.<n> | always-on evidence gate; scanning Fill source; judging pass/fail from the manifest |
| **G7** | Contract-drift consistency gate: compare bind-first schema/contract/decision-log hashes with normalized v1 fields and the final append-only decision log. Emits stable machine-readable failures for unrecorded drift; never claims to prove user identity or consent | treating an agent-written decision record as self-approval; semantic product judgment |
| **Blocking** | Acceptance failure that must recirculate (L5/L6, unsafe ops, …) | optional polish |
| **Dogfood** | Run Design I/O on a real UI ask to test *process*, keep answer not demo code | shipping the throwaway page |
| **run aggregate** | Cross-run rollup from `scripts/aggregate_runs.py`: per-run status table + repeat-blocker frequencies over `.scratch/**/dogfood/*/` runs; JSON is the contract surface, markdown the view. Stays separate from `doctor.py` — doctor diagnoses install-state health of the distributable surface, aggregate reads this repo's run history; installed users have no `.scratch` (roundtable 2026-08-02) | a run ledger; prose “lessons”; a doctor check |
| **repeat blocker** | A blocker whose normalized `observed` text recurs across runs; systemic-defect signal; counting only, never judging (v0.9) | “we should learn…” narratives |
| **stable main** | Public distribution branch whose version and installable inventory exactly match the latest formal release; unreleased capability stays off `main` until its release gate passes | rolling development branch; prerelease surface under a released version |
| **release transaction** | Gated promotion of one identical release commit to `main`, one `vX.Y.Z` tag, the fixed npm release group (`design-playbook` + `dsh-design-playbook` at the same version, with the DSH dependency exactly `^X.Y.Z`), and one shared GitHub Release; before promotion, `main` remains the previous formal release | merge-first release prep; independent package versions or DSH tags |
| **SSOT** | Single source of truth for a declaration snippet | dual-edit attachments + references |
| **Native-feel** | Desktop app indistinguishable from native; render-surface seam + native conventions; declared by `native-craft` | “theme Electron”, “web page in a window” |
| **Run View** | Rebuildable, source-linked projection of one Closed-loop run that exposes intent, current verdict, blocker ownership, next action, criterion coverage, and limitations. It may offer typed actions routed to existing authority owners, but has no generic write path or independent decision, Evidence, or verdict state | `DesignRun` aggregate; generic dashboard; Workspace status as acceptance; raw artifact dump |
| **Closed-loop Run Console** | Local, plugin-delivered Run View for a real repository. Its primary job is to let a Run operator understand intent, source verdict, blocker source, next owner, and the Criterion → Evidence → Finding → Repair path without opening raw run artifacts | Design Workspace; Canvas; generic status dashboard; new run-state store |
| **Run snapshot** | Consistent materialization of one Run View bound to the source hashes used to build it. Refresh replaces the whole projection from authoritative sources; stale, partially written, or unknown facts stay visible and never fall back silently to the last successful snapshot | live run state; Console-owned cache as authority; mixed-time reads presented as current |
| **Snapshot model** | Seven-part domain shape for a Run snapshot: identity, intent, execution, evaluation, next actions, limitations, and sources. It is organized by user-meaningful assertions, not by artifact filenames or Console components | file mirror; page view-model; permanent run history |
| **Assertion availability** | Independent quality axis for a Run snapshot assertion: `known`, `unknown`, `stale`, or `inconsistent`, with a reason and source metadata. It never substitutes for the assertion's domain result such as verdict or gate outcome | one global status enum; treating stale as failure; treating unknown as pending |
| **Source locator** | Opaque, run-scoped reference that resolves server-side to an allowlisted authoritative artifact and optional semantic anchor. Browsers never receive arbitrary, relative, or absolute filesystem paths | raw path; browser-supplied file locator; unrestricted file-open endpoint |
| **Run operator** | Human accountable for invoking and completing a run in a real product repository; the initial beachhead is a frontend or product engineer using Claude or Codex. Operating a run grants no blanket semantic approval authority | every viewer as an operator; operator as universal approver; tool-vendor-first user |
| **Semantic approver** | Human acting in a named product, design, or engineering role with authority to confirm a normative claim in that role. One person may hold multiple roles, but continuing a run never implies cross-role approval | Agent self-approval; operator click as blanket approval; machine facts as semantic judgment |
| **Role attestation** | Run-local statement of the product, design, or engineering role in which a human confirms a normative claim. It scopes the confirmation but proves neither real-world identity nor organizational entitlement | authenticated identity; organization membership; one click approving every role |
| **Diagnostic export** | User-initiated, reviewable summary selected for an invited trial and exported from local run facts to support product diagnosis. It is never collected silently and excludes secrets, raw model reasoning, source code, and unselected artifacts | hidden telemetry; automatic upload; full run archive; analytics consent inferred from installation |
| **Trial participant ID** | Random pseudonymous identifier created at invitation and deliberately retained by the participant across Diagnostic exports. It supports repeat-use measurement without a name, account, device fingerprint, or hidden identifier | user identity; machine fingerprint; authenticated account |
| **Comprehension check** | Timed four-answer trial measure taken from the Console: intent, source verdict, blocker source, and next owner. Answers are compared with the Run snapshot; subjective usability opinion and passive dwell time are separate inputs | satisfaction survey alone; hidden interaction analytics; page-open duration |
| **Maintainer intervention** | Assistance beyond public install/use documentation that changes a run or helps a participant derive a trial answer. It is disclosed in the Diagnostic export; neutral interview prompts that do not reveal answers or alter the run are not interventions | only direct code edits; any researcher speech; unrecorded pairing |
| **Qualified audited run** | Invited-trial run for a P2/P3 change in an existing Web product with the Evaluator enabled, at least one Manifest-bound rendered or interaction Artifact, a final point-back record, and every maintainer intervention disclosed | any successful command; unaudited skeleton; first-pass-only run |
| **Voluntary repeat** | A participant independently starts another Qualified audited run for a different real UI work item after the first run ends. Repair attempts inside one run, reopening the Console, maintainer-scheduled demos, and repeated exports do not count | retry; revisit; same-run recirculation; prompted demo |

## Decisions (grill)

- **First-party UI/UX ownership boundary:** design-playbook owns its capability matrix, artifact contracts, gates, evidence semantics, and recirculation. User-provided external and local references may expose missing capabilities or conflicts, but they are neither product dependencies nor rule authorities. The core model stays platform-neutral; Web is the first automated validation surface.
- **External benchmark absorption (2026-08-28):** absorb ideas from an external official skill (benchmark input only; external product/skill names stay out of product content): the Anti-default check at compare/explore tiers (ui-picker step-4 prose + advisory DECIDE-family registry rule), a COPY advisory rule family (active voice, user-side naming, error tone — English prose covering Latin + CJK; the craft.md/ux-spec functional skeleton stays untouched), a focus-visible positive rule in the A11Y family, structure-is-information and CSS-specificity advisory rules in the CRAFT family, and the Memorable element prose expectation on E-tier DD entries. Every new rule enters at advisory with user confirmation recorded here. Rejected: a responsive floor (RESP-01 already closes it), thinking-only planning and unconditional aesthetic risk (conflict with confirmation authority), hero-as-thesis as a universal rule. Dogfood evidence (2026-08-28, 17 visual runs) shows zero convergence on the benchmark's three described default looks but convergence on two self-observed defaults — light slate + white-card + teal/blue admin, dark ops console + muted blue/cyan — so the Anti-default check's dated examples name our own observed defaults, never an external list. Ships next version, not v0.21.1.
- **External-name boundary (2026-08-28):** product content (skills, references, the rule registry, glossary) and repo agent instructions carry zero external product/skill names; absorbed ideas are re-expressed first-party and registry entries mark `provenance: benchmark-input-only`. The README ecosystem-stacking table and the codex routing lines stay as deliberate attribution/routing exemptions (ADR-0002; validate.py attribution and routing exemptions). The infringement vector — copied text — is closed by first-party original wording; nominative attribution with links remains.
- **Roadmap operating frame (2026-08-25):** keep the 12-month Design OS direction as a conditional, falsifiable north star; only a rolling 90-day horizon is a delivery commitment, with explicit acceptance thresholds, stop conditions, resource assumptions, and non-goals. The current horizon assumes one maintainer plus coding agents; later platform phases require a stable, explicitly committed 2-4 person team rather than speculative staffing.
- **Next-horizon beachhead (2026-08-25):** the primary Run operator is a frontend or product engineer using Claude or Codex to deliver UI in a real product repository. Product, design, and engineering Semantic approvers retain role-specific authority; selecting the operator does not transfer all semantic approval to engineering.
- **Run View authority boundary (2026-08-25):** the 90-day visible product surface is a local, source-linked projection and typed facade over existing authorities, never a new `DesignRun` source of truth. Human approvers own durable semantic promotion, deterministic validators own reproducible machine facts, and Agents propose and execute without self-promotion (ADR-0035).
- **90-day outcome and trial scope (2026-08-25):** prove that a Run operator can understand intent, verdict, blocker source, and next owner within 60 seconds and complete `Recirculate → repair → Pass`, then choose to repeat the workflow. Invited trials cover P2/P3 changes in existing Web products with at least one rendered or interaction Criterion; greenfield, multi-platform, and Canvas workflows remain outside the trial.
- **Console sequencing (2026-08-25):** establish deterministic read parity before adding a narrow typed-action allowlist. Actions may reveal an authority source, request a role-scoped confirmation, or invoke an already-authorized next step through its existing owner; arbitrary artifact editing, generic run mutation, and a full workflow control center are excluded.
- **Evidence evolution boundary (2026-08-25):** retain `execute_capture_plan` as the single Provider collector seam for the 90-day horizon. Improve Manifest binding, Evaluator reasoning, and Console visibility rather than splitting criterion-aware judging across specialized MCP tools; Providers still produce Artifacts, never Evidence or verdicts.
- **Invited-trial data boundary (2026-08-25):** validation uses local invited trials and explicit Diagnostic exports. Installation or participation never implies telemetry consent, and Role attestations scope local confirmations without claiming verified identity (ADR-0036).
- **Current public promise (2026-08-25):** describe design-playbook as **evidence-backed UI delivery for coding agents**. `Design I/O` names the mechanism; `Design OS`, `CI/CD for AI-generated UI`, and Workspace remain unvalidated north-star language rather than current product claims.
- **Console delivery and navigation (2026-08-25):** the Console is an on-demand, loopback-only local Web application opened for one explicitly selected run. A recent-run locator may help choose that run, but the Console does not become a project dashboard, persistent daemon, cloud service, cross-run report, or organization Workspace (ADR-0037).
- **Snapshot and approval semantics (2026-08-25):** the Console builds a source-hash-bound Run snapshot, then rebuilds it on explicit refresh or after a known typed action. Stale, partial, and unknown facts are visible. Each normative claim names its required Semantic approver when one is needed; a missing Role attestation blocks only results that depend on that claim, with no global product/design/engineering approval gate (ADR-0037).
- **Invited-trial acceptance floor (2026-08-25):** evaluate the 90-day direction only after at least five unrelated external users across at least three real repositories complete at least ten audited runs, including at least five `Recirculate → repair → Pass` loops; at least three of the five users must voluntarily repeat within 30 days. Diagnostic exports are versioned JSON contracts plus local Markdown views that the participant previews and shares manually.
- **Run snapshot contract and local threat model (2026-08-25):** expose a versioned domain JSON contract rather than UI component state or raw artifact layout. Assertion availability and domain result are separate axes; each important assertion carries a Source locator, source hashes, freshness, and an unknown/inconsistent reason. Loopback is untrusted: the Console uses an unguessable session token, validates Origin, keeps GET side-effect-free, and protects every action request (ADR-0038).
- **Initial Console action allowlist (2026-08-25):** refresh, resolve/view an authoritative source, copy the next Agent command, request a Role attestation through its authority owner, and generate a Diagnostic export. Direct repair execution, automatic reruns, arbitrary file edits, and automatic acceptance are excluded from the invited-trial horizon.
- **Trial measurement protocol (2026-08-25):** count only Qualified audited runs and Voluntary repeats. The minimum Diagnostic export records pseudonymous trial/run IDs, product and schema versions, non-secret environment facts, tier, phase durations, outcomes and counts, blocker categories, disclosed human intervention, comprehension answers, and repeat status; raw text is excluded unless the participant explicitly selects a specific excerpt.
- **README claim boundary (2026-08-25):** update the public front door now to the delivered claim **evidence-backed UI delivery for coding agents**. The Closed-loop Run Console is labeled a planned invited trial until implemented and verified; Design OS remains confined to roadmap material.
- **Snapshot model and compatibility (2026-08-25):** the disposable Run snapshot uses the seven-part Snapshot model and is rebuilt rather than archived. The Console and snapshot schema ship in lockstep and reject unknown versions; permanent backward readers are reserved for versioned Diagnostic exports, the only new persistent trial record. Authority-source viewing renders a server-resolved read-only semantic excerpt and anchor, never launches an editor, exposes a path, or permits browser editing (ADR-0038).
- **Role-attestation binding (2026-08-25):** a confirmation request binds the claim ID and claim hash, requested role, and current authoritative source hash. Only an explicit human submit lets the existing owner persist the confirmation; any bound source change invalidates it, and confirmation never transfers across roles (ADR-0038).
- **Trial identity, comprehension, and intervention (2026-08-25):** repeat measurement uses a participant-retained Trial participant ID, never an account or machine fingerprint. Each Qualified audited run uses the fixed Comprehension check, and every Maintainer intervention is disclosed so assisted success cannot masquerade as self-service completion (ADR-0036).
- **Trial export containment (2026-08-25):** Diagnostic exports live under the selected run's `trial-export/` subtree and are labeled non-Evidence and non-acceptance input. They never enter `evidence/`, affect a Manifest, or participate in Evaluator verdicts (ADR-0036).
- **90-day delivery order and beta gate (2026-08-25):** contract freeze → read parity → secured single-run Console → external read-only trial → typed actions → expanded trial. Public beta requires every existing trial quantity threshold plus zero competing writes, zero unexplained sensitive-data disclosure, and 50 consecutive snapshot rebuilds with zero semantic drift; elapsed calendar time never graduates the product automatically.
- **Preview versions primitives:** versions.py consumes the durable decision authority through `transaction.py`'s public API — `atomic_write`, `directory_lock`, `json_text`, `load_entry`, `load_confirm_for_entry`, `render_log`, `valid_entries` — instead of underscore-privates, and the version writer lock reuses the single directory-lock policy from transaction (the duplicated `VERSION_LOCK_*` timeout/stale/heartbeat/poll constant set is deleted; `.versions.lock` stays the version lock filename). The reverse seam is public too: transaction imports `versions.render_versions_log`. Zero artifact/behavior change; preview transaction/versions/integrity/stdio tests stay green (ADR-0024).
- **Closed-loop validation deepening:** packaged `scripts/validate_run.py` splits into focused gate modules — `g1_spec.py` (G1), `g2_g4_pointback.py` (G2-G4), `g5_preview.py` (G5), `g6_evidence.py` (G6) — with a thin CLI orchestrator keeping `run()`/`_parse_args()`/`main()`, the finding-aggregation order, strict-mode require flags, and the optional G7 import. Rule IDs, message strings, exit codes, CLI flags, and help text are preserved; gate modules import `design_playbook.*` absolutely and are not entry points (ADR-0023).
- **Import seam deepening:** the bundled Python surface is one real package (`design_playbook`) with a single guarded package-root bootstrap; every entry point (scripts, MCP servers, tests, dev tools) imports absolute `design_playbook.*` instead of per-runtime `sys.path` adapters. The root `scripts/run_status.py` dev copy is deleted; the packaged copy is the single source (ADR-0022).
- **Stage registry module:** packaged `scripts/stages.py` owns the Design I/O stage list (`STAGES`, the SKILL.md step mirror for status/resume narration) and the shared artifact names (`evidence/`, `evidence/manifest.jsonl`, `point-back.md`, `decision-report.md`, `spec.md`). `run_status.py` (both copies) and `validate_run.py` (G6 `EVIDENCE_PREFIX`) consume it; the registry has one home and one drift surface (ADR-0021). Preview stage presence stays derived by Preview integrity; the persistent-contract `decisions.jsonl` stays with ADR-0017.
- **Capture contract deepening:** bundled Evidence runtime owns capture-contract rules in one package-internal module at `mcp/evidence/capture_contract.py`. Its interface provides write-side parse/normalize (`parse_capture_contract`), read-side full-shape validation of manifest request snapshots (`validate_capture_snapshot`), and the contract-fields JSON Schema fragment the provider tool schema composes. Provider keeps Runtime Object fields, path/overwrite boundaries, and Playwright I/O; G6 consumes the same validation instead of hand-written partial checks. Sanctioned correction: bound evidence snapshots with malformed viewport shape or missing freeze fail closed (was lax); real orchestrator snapshots already carry freeze via provider echo.

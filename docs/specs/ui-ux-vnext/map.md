## Destination

Resolve every product decision needed to author an implementation-ready vNext specification for design-playbook's first-party UI/UX capability matrix: interactive requirement shaping, tool-neutral design decisions, dual-track implementation review, evidence gates, and recirculation. External references remain research inputs only, never dependencies or rule authorities.

## Notes

- Domain: `CONTEXT.md`; consult `/wayfinder`, `/grilling`, and `/domain-modeling` for decision tickets, and `/research` for research tickets.
- Product ownership: design-playbook owns the capability matrix, artifacts, gates, evidence semantics, and recirculation.
- Core concepts are platform-neutral; Web is the first automated validation surface.
- Planning only: this map resolves decisions and exposes the route to a vNext spec. It does not implement or release code.
- Reference material: user-provided local study notes and external UI/UX benchmark samples. Rephrase and validate any promoted idea; do not publish source names, local paths, or copied third-party rule text.

## Decisions so far

- [研究：梳理 design-playbook 现有 UI/UX 能力与缺口](https://github.com/Bandersnatch0x/design-playbook/issues/26) — Existing lifecycle, authority, gates, and evidence binding are mature foundations; stateful requirement shaping, path ownership, rule governance, machine-traceable recirculation, and learning promotion remain incomplete.
- [研究：从 HCI 资料提炼可验证的第一方能力候选](https://github.com/Bandersnatch0x/design-playbook/issues/27) — The loop must bind user, task, context, and checkable outcomes; automation may verify reproducible facts, while subjective and representative-user claims require human evidence.
- [研究：比较 UI/UX 参考样本的能力覆盖与冲突](https://github.com/Bandersnatch0x/design-playbook/issues/25) — The samples expose useful partial capabilities but no complete acceptance-to-evidence-to-recirculation loop, reinforcing the need for first-party, tool-neutral artifacts and rule governance.
- [定义第一方 UI/UX 功能矩阵与产品边界](https://github.com/Bandersnatch0x/design-playbook/issues/24) — First-party matrix confirmed as eight domains — interactive requirement shaping, interaction modeling, tool-neutral design decisions, dual-track implementation review, evidence binding, point-back recirculation, rule governance, and cross-run learning — with consequence-graded decision authority, advisory-by-default subjective findings, and promotion-gated machine enforcement.
- [原型化交互式需求成形的决策模型](https://github.com/Bandersnatch0x/design-playbook/issues/28) — Stateful shaping session model S0-S6 with consequence-graded questioning and batched confirmation points; assumed fields age into mandatory questions after two acknowledged runs; session artifacts follow an alive→archived→discardable lifecycle and reopening always starts a new session; the contract stays the sole persistent decision authority (sessions project into it, no bypass), with a zero-breaking contract v1 extension.
- [原型化 UI/UX 实现评审与证据模型](https://github.com/Bandersnatch0x/design-playbook/issues/29) — Dual-track review finalized: product/interaction/cross-cutting dimensions with a fact-vs-judgment axis split — severity and disposition are separate axes, judgment-class S3 never blocks without user escalation — an implemented-UI pass requires a bound rendered or interaction artifact, coverage uses a five-state×page sampling matrix with an explicit-unreviewed duty and a machine-gated coverage statement in the six-block report, method semantics ride as optional manifest keys, and R1-R5 recirculation routing computes a minimal invalidated-evidence set.
- [定义第一方 UX 规则注册表与治理](https://github.com/Bandersnatch0x/design-playbook/issues/30) — Unified rule registry finalized as a product-level read-only declaration (`rules.md`, G8-self-validated) with stable family-serial IDs (CRAFT-01… kept verbatim), authority level orthogonal to enforcement status, three-state applicability predicates, and breaking revisions forking a new ID via supersedes; promotion to machine-enforced and its exemption are user-only decisions recorded in the append-only governance log, the craft-guard eight detectors migrate with zero ID breakage and the N/A contradiction is fixed by splitting applicability (three-state) from result (clear|hit), and the D8 candidate queue plus promotion criteria are defined as protocol only.
- [定义工具无关的设计决策协议](https://github.com/Bandersnatch0x/design-playbook/issues/31) — Tool-neutral design-decision protocol finalized with three-tier exploration scaled to consequence — record (R, direct entry) / compare (C, in-baseline candidates with agent-recorded trade-offs) / explore (E, user-confirmed identity or composition directions) — where in-baseline choices never trigger full exploration; the decision report deepens into versioned design-decision entry blocks behind the unchanged Fill-facing header; providers are replaceable data-contract adapters (candidate descriptors only) with reference-only assets (path+hash, never bound evidence); persistence is dual-track (visual → design-baseline, intent → decisions.jsonl projection, default run-scoped); comparison is a dimension×candidate matrix with explicit trade-offs and no scoring; user confirmation rides the preview transaction and G5 when present; R3 re-entry revises via supersedes with a minimal invalidation set, and baseline-drift re-review has three explicit outcomes with no calendar TTL.
- [定义端到端闭环工件、门禁与回流状态机](https://github.com/Bandersnatch0x/design-playbook/issues/32) — End-to-end loop finalized with tiered run profiles P1 point-fix / P2 standard / P3 full graded by declaration-touch surface (agent-proposed, user-confirmed once; promotion automatic, demotion user-only) so process weight scales with change consequence, an LR0-LR10 state machine reusing artifacts as the persisted state, a G9-G12 gate matrix extending G1-G8 (shaping exit, decision-entry integrity, coverage statement, tier boundary — all structurally non-waivable; only rule hits carry exemptions), a 19-artifact inventory where the sole new artifact surface is the mandatory run-profile block atop plan.md, and twelve re-entry events unified under minimal invalidation sets recorded in the point-back invalidated block; verdict stays Pass|Recirculate with escalation as run-status narration.
- [确定 vNext 产品表面、兼容边界与首个验证切片](https://github.com/Bandersnatch0x/design-playbook/issues/33) — vNext specification finalized: product surface mapping against the released v0.14.1 surface with six skills deepened or restructured (orchestrator, ux-spec, ui-picker, ui-evaluator deepened; craft-guard split into a registry reference layer; design-baseline gains the stale re-review record surface) and two untouched, zero command-signature changes with no new commands; only two breaking points against the released surface (the craft-guard detector table switching atomically to the seven-column three-state format with zero ID breakage and no rewrite of historical run artifacts, and severity old values carried through a two-minor alias window), everything else zero-break or additive; the first Web validation slice combines the craft-guard migration, run-profile block, and shaping-session artifacts into a P2 standard-run closed loop with five machine-checkable exit criteria on the existing CI/validate surfaces; and an S1-S6 versioned delivery-slice sequence with per-slice minor releases (v0.15.0 = S1 through v0.20.0 = S6, v1.0 deferred to the post-external-user-signal milestone), with implementation entered through the single S1 ticket (#34) while S2-S6 tickets wait for S1 validation.

# v0.25.1

Patch release prepared 2026-09-26. It closes the defect batches found while
verifying the v0.25.0 release candidate, adds one additive **read-only**
projection to the existing `run-status` surface, and separates local
maintainer planning from shared documentation.

The published surface is unchanged in shape: **9 skills / 8 commands**, the
same two bundled MCP servers, and no new gate or rule-registry entry
(ADR-0015 stable main — a patch release cannot move the version-line
inventory). `COMMAND_INVENTORY` keeps its `(0, 25)` row.

## Read-only frontend scope review

`run-status` can now answer "what does this change actually touch, and which
declarations and L6 criteria does that reach?" for an explicit scope, without
starting a run, a server, or any Console capability.

```
python packages/design-playbook/scripts/run_status.py <run> --scope path:P1 --json
```

- New module `packages/design-playbook/scripts/frontend_review.py` (read-only
  projection); the entry point stays `run_status.py --scope`. Without `--json`
  the same facts render as text.
- Scope reaches declarations and L6 criteria through a traceable mapping. When
  a component/file association does not exist the result stays `unknown`, and
  the derived candidate set is never allowed to narrow the original owner's
  invalidated set (`can_narrow=false` as the recorded interpretation).
- Evidence gaps are reported on separate axes — requirement, status/viewport,
  and binding — with one key shape per `evidence_gaps[].bindings[]` member and
  a declared `schemaVersion: 1`.
- Capture metadata is validated from manifest capture entries; a missing
  capture metadata set fails closed, and only screenshot-derived probe
  sidecars are accepted as proof metadata.
- An owner ledger that exists but cannot be projected no longer collapses into
  "missing": its gaps carry the `pointback-malformed` reason and availability
  becomes `inconsistent`. The latest binding is the latest `ts` **instant**,
  not the largest string; a timestamp without an offset fails closed as
  `invalid-binding-timestamp`.
- G1/G11 expose derived read values from their existing parsers instead of
  re-parsing, and G6 shares the latest-binding selection and rejects
  conflicting newest records. Console Snapshot v1 is unchanged.

This slice was authorized under
[ADR-0045](https://github.com/Bandersnatch0x/design-playbook/blob/main/docs/adr/0045-external-evidence-spend-gate.md)'s
bounded self-use exception. It adds no write path, no automatic
repair/rerun/acceptance, and no new UI or service. It is not evidence of
external validation, and the paired real-task measurement closed as
`INSUFFICIENT` at 0/3 real samples.

Five findings from the release-candidate verification report:

  waive in **every run** must be stated to that run's user — a stored value is
  not that user's consent.

  interface (`--intent` / `--consequence` are required; `--repo-root` /
  `--request` did not exist).

  `run_root` → env → cwd), so a `--plugin-dir` dev session no longer silently
  captures into the repository root; the T-063 warnings and `doctor.py` point
  at that same repair.
- Interaction trace artifacts are named by their real bytes: a Playwright ZIP
  named `.json` is now rejected by one rule
  (`path_syntax.trace_artifact_error`), and the a11y artifact is documented as
  a `{format, tree}` envelope. Four skills and three references were aligned.
- The Approve pill and kbd hints no longer wrap or clip under English
  rendering.

## component-distill defect batch (T-088)

Seven breakpoints from an end-to-end backflow replay. D1/D3/D4/D5/D7 were real
defects and are fixed with regressions; D2 and D6 were reclassified and are
recorded as boundaries instead:

- **D1** — decision reports without a fenced block produced a silent **zero
  candidates**. The parser now degrades or reports explicitly instead of
  emitting nothing.
- **D3** — truncated fragments such as `无组件(纯文本单元格,category` entered the
  candidate pool; the filter now rejects them.
- **D4** — the `scene` count could never be < 2; the predicate is corrected.
- **D5** — `promote` now re-checks the qualifying conditions at execution
  time, not only at decision time.
- **D7** — a repeated `verify` no longer misreports an accepted overwrite.
- **D2** — candidate identity is the file path, so table/badge/toolbar/sidebar
  collapse into one candidate. This is the current schema's intended
  granularity; a finer component-level identity is a schema migration.
- **D6** — user adjudication carries no authentication. The read side already
  fails closed; write-side strong identity is a separate boundary.

Also documented, not a defect: a promoted `DESIGN.md` entry binds
`source_sha256`, so editing `src/App.css` afterwards makes `verify` fail
closed and requires a new adjudication.

Replay after the fixes: the four historical reports parse to 36 references and
false candidates are filtered out.

## Piped-output encoding on non-UTF-8 hosts (T-105, T-081 family)

The release gate itself exposed a shipped defect, and an audit afterwards
closed the whole class rather than the two files that happened to break.

On a host whose code page is not UTF-8 (`cp936` on a zh-CN Windows
installation, `cp1252` on a Western one, `shift_jis` on a Japanese one), a
Python process writes to a **pipe** using that code page, while every consumer
of these entry points reads UTF-8. Two failure modes follow:

- **silent corruption** — the bytes are the code page's encoding of the text,
  so a UTF-8 reader gets an invalid document. `run-status --json` serialized
  the narration `point-back.md present — confirm ## Verdict, then stop or
  recirculate.` with its em dash as `0xa1 0xaa`, i.e. **JSON that is not valid
  UTF-8**, which is what a JSON document is required to be.
- **crash instead of report** — when the code page cannot represent the
  character at all (`shift_jis` has no em dash, `cp1252` has no CJK), the
  entry point dies with `UnicodeEncodeError` before printing its message.

The gate surfaced it as `scripts/release.py` reading a green child as
`validate.py failed (exit 0)`: the strict UTF-8 reader thread raised, and the
child's stdout arrived as `None`.

### What changed

- **One seam.** `packages/design-playbook/scripts/stdio_encoding.py` now owns
the rule (`configure_piped_utf8()`), and every non-test entry point — **38
migrated files** across the bundled `scripts/`, both MCP servers,
`codex/install_skills.py` and the maintainer `scripts/` — calls it from its
`__main__` block. The eight files that already carried a hand-written guard
were migrated to it, and the two that guarded stdout but not stderr
(`doctor.py`, `evidence_preflight.py`) are fixed by the same call.
- The MCP servers need no seam: `mcp/_transport.py` writes JSON-RPC through
  `sys.stdout.buffer` as UTF-8 bytes. A handshake is now byte-identical on
  every code page, and that is pinned by a test so a future `print()` cannot
  quietly reintroduce the defect. The `design-baseline` skill payload keeps
  the rule inline, because it must still run when it is copied out of the
  plugin and this import seam is unavailable.
- Readers stop being the encoding police: `release.py`'s subprocess helper and
the seam harness decode with `errors="replace"`, so a stray byte can no longer
  turn a green child into a confusing failure. The UTF-8 guarantee itself is
  asserted strictly.
- **`tests/test_stdio_encoding.py`** enforces both directions: a static net
  (an entry point that forgets the seam fails by name, including entry points
  whose non-ASCII text only appears on paths no test reaches) and a dynamic
  sweep (every entry point runs under `cp1252` and `shift_jis`, asserting
  UTF-8 bytes and no `UnicodeEncodeError`). Both nets were verified red before
  the fix: removing one seam call failed the static net naming
  `g6_evidence.py`, and the sweep reported
  `g6_evidence.py --help [shift_jis]: 1 non-UTF-8 byte(s) on stdout`.

### Audit scope

A repository-wide static audit (`ast`, docstrings excluded) covers all 223
tracked Python files: 92 carry non-docstring non-ASCII literals, 23 of them
entry points, of which 8 had a pipe guard before this change. The empirical
sweep found **32 breaking invocation × codec combinations across 9 entry
points** — `contract_v1.py`, `g1_spec.py`, `g2_g4_pointback.py`, `g5_preview.py`,
`g6_evidence.py`, `g9_shaping.py`, `g10_design_decisions.py`, `shaping_log.py`
and `evidence_preflight.py` — and **0 after** the sweep, under `cp1252`,
`shift_jis` and `gbk`, with the tree re-verified unmodified by the sweep's own
invocations.

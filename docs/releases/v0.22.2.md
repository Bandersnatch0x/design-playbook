# v0.22.2

Patch release prepared 2026-09-10. It keeps design-baseline rejections
visible and existing DESIGN.md overwrites recoverable, and adds a run-status
diagnostic for Fill declarations written inside fenced blocks.

## Baseline rejection stays visible

When `prepare()` finds a project-root candidate DESIGN.md that fails baseline
validation, the rejection reason is no longer discarded. `needs_confirmation`
state now carries a `baseline_rejection` `{path, reason}` fact (absent when no
candidate exists, omitted entirely when the candidate validates and the run
proceeds to `ready`), and run-status projects that reason into the Fill
blocker label.

## DESIGN.md overwrites become recoverable

`confirm(accept)` still replaces an invalidated canonical DESIGN.md — that
path is by design — but it no longer does so silently. When the canonical
file exists with different content, it is byte-copied to
`design-baseline/previous-DESIGN.md` before the draft is written, the accept
state records `replaced_baseline` `{path, sha256, backup}`, and the CLI prints
a stderr WARNING naming the backup. A canonical file that cannot be hashed
blocks the overwrite instead of proceeding unprotected.

## Fenced Fill declarations are diagnosed

Fill declarations only take effect as column-0, unfenced `fill: <path>`
lines in plan.md; the same line inside a fenced block is prose, not a
declaration. Run status now reports such fenced lines explicitly (text
diagnostic plus a `fenced_fill_declarations` JSON field) instead of silently
skipping them, so an agent whose declaration was swallowed can see why its
Fill stage stayed empty.

## Verification

Ten new tests cover the rejection fact, byte-identical backup and sha256
record, no-backup-on-clean-accept, the CLI warning, fenced-declaration
capture, and both run-status renderings. Full non-browser suite passes
(tests/ + packages/design-playbook, mirroring the CI groups): 892 passed,
242 subtests passed; release gates (validate.py, seam, adapter) green.

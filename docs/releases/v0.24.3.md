# v0.24.3

Patch release prepared 2026-09-20. It ships architecture-deepening round 6:
the adapter subsystem's discovery, drift-compare, and marker knowledge each
collapse to a single owner, the Run Console snapshot builder reads through
its owner seams and derives observation digests from what its projection
owners actually read, and the rule registry's prose consumers are pinned to
the registry. No user-facing behavior changes: adapter renders are
byte-identical (29 agents / 75 files verified against a pre-refactor
baseline), and the doctor's blocking/report semantics are unchanged.

## Adapter subsystem — one owner per fact

- **Derived artifact discovery.** The packaged doctor no longer carries a
  hand-maintained shadow map of every renderer's output paths; its
  discovery and orphan scans derive from the `render_entries` read seam
  per matrix row (probe out-dir never created, fully read-only). Adding an
  agent or changing an output layout updates discovery through the
  generator seam alone — the ADR-0042 "adding an agent = adding a matrix
  row" promise now holds for paths, not just code.
- **One drift compare.** The committed-snapshot compare algorithm existed
  twice (the blocking validate.py gate and the read-only root doctor
  report), both shelling out to the generator CLI and hardcoding "codex".
  It now lives once in `adapter_drift.py`, iterates
  `TIER1_SNAPSHOT_AGENTS` through `render_entries` in-process, and both
  gates are thin consumers with their semantics unchanged; every failure
  mode (missing, unreadable, drifted, render error) surfaces as a typed
  row. The gate gains direct unit tests.
- **Marker protocol single source.** `adapter_markers.py` owns the
  marker-block tags, the per-syntax generated-by comment forms, and the
  detection/normalization regexes; the generator, the packaged doctor, and
  the tests import from it. Changing the marker format touches one module
  (the last such change, issue #115, touched four-plus sites).
- **Matrix flags retired.** The capability flags (rules / commands /
  mcp_project / hooks / skills / rules_target) had no production consumer —
  dispatch is the name-keyed renderer map plus the AGENTS.md floor. They
  are removed from `AgentRow` (ADR-0042 amendment), and published agent
  counts (both READMEs, AGENTS.md, the package README) are derived from
  the matrix and enforced by a validate.py gate — the stale 29-agent
  claims are fixed to 30.

## Rule registry — one parser answer

`g10_design_decisions` drops its private copy of the registry parser
(entry-heading regex, version-field parse, registry path triple) and uses
the shared `rules_registry` parser, so G10 and G8 cannot disagree about
what a legal entry is. Every `ID@ver` version pin on a skill surface
outside rules.md is now checked against the registry's current version by
a validate.py gate (slash shorthand `COPY-01/02/03@1` expands with family
prefixes), and the CRAFT example-fixture coverage derives from the
registry with CRAFT-09/10's fixture-less state recorded explicitly.

## Run Console — owner-carried reads and observed digests

- The snapshot builder no longer re-reads `evidence/manifest.jsonl` or
  `.claude-plugin/plugin.json` through a second parser: the manifest text
  rides the `RunFacts` capture and the package identity projection carries
  its captured text and read state (each file read once per capture pass
  instead of twice per pass through two parsers that could disagree on a
  torn write).
- The builder's cross-phase mutable state (`manifest_degraded`,
  `limitations`) becomes an explicit projection value returned by the
  projection phase, removing order-dependent coupling.
- Observation digests derive from an access-time read log of the
  projection owners instead of hand-maintained input lists. Two staleness
  holes close: a mid-build change to `design-baseline/state.json` content
  or to a run-external fill artifact now turns the dependent next-action /
  stage-registry assertions stale instead of shipping `freshness: current`
  with stale values. Mutation tests pin both cases.

## Hardening and hygiene

A regression test pins the Run Console's graceful connection teardown
(full response plus clean EOF when a POST leaves body bytes unread; the
Windows TCP-reset defect cannot return silently). `validate_run` reads the
decision report from the captured facts unless an explicitly passed path
points outside the captured run root. The two same-named `doctor.py`
files cross-reference each other in their docstrings.

## Verification

Adapter renders verified byte-identical against the pre-refactor baseline
(29 non-native agents, 75 files). Full local suite green (1829 tests +
1332 subtests plus the operator continuation e2e); release gates (validate,
seam, adapter floor) green; the two-axis review (standards + spec
compliance) closed with one P0 fix — a corrupted pin-gate regex plus a
slash-shorthand expansion defect in the same gate, caught by review and
now pinned by a permanent tamper test.

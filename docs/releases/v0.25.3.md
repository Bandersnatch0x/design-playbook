# v0.25.3

Patch release prepared 2026-09-30. It adds the **project-bound slash
integration** for the local asset workbench to the plugin's published
surface, and repairs the Evidence MCP server's run-root forwarding. The
workbench service itself is a **separate, independently distributed Python
package that is not part of this release** — see *Release boundary* below.

The published surface is unchanged in shape: **9 skills / 8 commands**, the
same two bundled MCP servers, and no new gate or rule-registry entry
(ADR-0015 stable main — a patch release cannot move the version-line
inventory). `COMMAND_INVENTORY` keeps its `(0, 25)` row.

## Project-bound slash integration

Slash commands are prompt text, so "which project is this run about?" has to
be a real, checkable step rather than a sentence an agent may interpret
loosely. Seven pipeline commands (`design-io`, `ux-spec`, `ui-review`,
`run-status`, `run-review`, `run-handoff`, `component-distill`) now carry a
Project target resolution block backed by two new bundled scripts:

- `packages/design-playbook/scripts/project_target.py` resolves the target
  from adapter metadata or an explicit configuration — never from the current
  working directory. A project-level install binds the marked project; a
  user-level install refuses to guess and requires an explicit absolute
  directory (or a registered project id). The home directory, the plugin
  install directory, the cwd, and any previous target are never used as a
  fallback.
- The answer comes from the local workbench service, which is the authority
  for bindings. **Without a workbench request, an explicit absolute directory
  still resolves while the service is stopped**, so the pre-workbench slash
  workflow keeps working: nothing is registered and no competing, offline
  asset directory is ever created. With a request, or a registered project
  id, the service must be running — otherwise the result is `unavailable` and
  the command stops.
- `packages/design-playbook/scripts/publish_owner_projection.py` is the
  owner-side, transcript-only writer for the projection document the
  workbench reads. It adjudicates nothing, preserving the ADR-0045 authority
  partition (the workbench keeps locators and projections, never a second
  verdict, baseline, or evidence authority).

## Evidence MCP run-root forwarding

`packages/design-playbook/.mcp.json` now forwards `DESIGN_PLAYBOOK_RUN_ROOT`
through an `env` object with `VAR:-` interpolation (the Claude `.mcp.json`
schema), and `capture_runtime.py` treats an unexpanded interpolation token as
unset, so a `--plugin-dir` dev session no longer silently captures into the
repository root (ADR-0009 amendment).

## Release boundary: the workbench is not published here

`packages/design-playbook-workbench/` — the local, loopback-only
single-maintainer asset workbench authorized by the ADR-0045 2026-09-26
amendment — is a **separate Python distribution**
(`design-playbook-workbench`, `requires-python >=3.12`, no dependencies). It
is **not** in this release:

- it is not in the plugin tarball (`package.json` `files`);
- the fixed npm release group is `design-playbook` + `dsh-design-playbook`
  only, and `release.py`, `validate.py`, and `doctor.py` do not reference it;
- it has no marketplace entry, and **no public distribution channel** (no
  PyPI workflow) is configured.

Workbench delivery is **not verified**. Its own delivery ticket (`WB-14`) is
kept `open`:

- **A11 blocked** — the two-target **real Agent-host journey** has not been
  run (no approved host on the maintainer machine); only the protocol layer
  is tested.
- **A12 blocked** — depends on the A11 host run.
- **A15 blocked / not-run** — clean-target install (locally verifiable part
  only), Windows ACL / junction / file-occupation evidence, the Ubuntu CI
  run, the R15-scale p95 measurement, and a real Python 3.12 run.

ADR-0045 states that a missing, blocked, or unrun required path leaves the
capability undelivered, and that authorization to implement is not a
completion claim. This patch therefore carries the plugin-side integration
only and makes **no claim** that the workbench exists as a deliverable or is
publicly installable. The API-driven closed loop recorded under
`.scratch/real-loop-20260930/` is a **protocol** exercise, not the real
Agent-host journey ADR-0045 requires, and is not counted as acceptance
evidence.

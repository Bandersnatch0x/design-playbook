# v0.25.5

Release prepared 2026-10-24. It lands the preview control shell consolidation
that had been developed on its own branch, together with the personal asset
workbench the maintainer has been building against specification R01-R15: a
local loopback service, its browser surface, agent task handoff, owner
backflow, archive and lifecycle, and backup/restore.

The workbench is a **separate package** and is not part of the published npm
artifact's runtime. This release ships the plugin surface; the workbench
installs on its own. See "Release boundary" below.

## Preview control shell

The Preview surface gains a consolidated control shell: a single place for the
edits a maintainer makes while reviewing, with the edit ledger and the
host-authority rules kept where they were. Multi-file staging, the host
transaction, and the rollback path keep their existing contracts; the shell
only changes how they are reached.

## Personal asset workbench

A local, loopback-only workbench for one maintainer's design assets. It binds
`127.0.0.1`, keeps its data in a private data directory, and never opens an
outbound connection. In this release it covers:

- **Projects and assets**: register a folder, import its design material, and
  browse what was imported with the capability each carrier actually has.
- **Revisions and reuse**: published revisions are immutable; reference,
  derive, copy, and upgrade are explicit, and a stale counter is a conflict
  rather than a silent overwrite.
- **Design system**: token documents with one parser and one validator across
  editing, preview, and publication; a baseline change stays an ordinary
  proposal and never edits `DESIGN.md` by itself.
- **Components and pages**: property, variant, and slot editing, layout
  validation against published components, and page-level dependencies.
- **Canvas**: boards, native editing, undo, and save with restart recovery.
- **Proposals**: multi-file change proposals with staged review, apply, and
  rollback when a write fails partway.
- **Agent task handoff**: a maintainer confirms the send scope, a real host
  claims the task with a protected local credential, heartbeats, and returns a
  result proposal. A result is never self-approved, and an expired lease is
  refused rather than silently accepted.
- **Owner backflow**: the original owner's projections are read as typed
  facts; a human confirmation binds to a content hash, and a passing criterion
  cannot become a backflow candidate.
- **Archive and lifecycle**: unregistering a project keeps its data, deleting
  it is a separate explicit action, and a referenced asset refuses hard
  deletion.
- **Backup and restore**: a consistent snapshot with a fixed blob manifest,
  restoration into a new directory, and key flows replayable after restore.

## Acceptance evidence

The workbench's A01-A15 acceptance ledger is recorded in the implementation
tickets rather than here. At this release, thirteen items are `pass`. The two
that are not:

- **Human keyboard acceptance**: the machine-checkable half is covered by
  committed browser journeys (panel close from the keyboard, skip-link focus,
  reading order, both desktop viewports, 200% zoom, focus indicators). Two
  subjective checks remain unrun: whether screen-reader names read sensibly,
  and whether state is conveyed without relying on colour.
- **A second clean machine**: installation was verified on an external
  directory of this machine (wheel into a fresh venv, neutral working
  directory, three HTTP probes) but not on a second physical host.

Both are recorded as `not-run`, not as passes.

## Release boundary

`packages/design-playbook-workbench/` is **not** in the published npm
artifact and is not installed by the plugin. Its wheel is built and installed
on demand (`python -m build --wheel` in that package). This release notes its
state so the capability is not mistaken for a shipped one; publishing it as a
distribution is a separate decision.

# v0.25.0

## Added

- **Component backflow / DESIGN.md promotion** (spec 2026-09-22, tickets
  T-067…T-072). The pipeline's backflow leg now covers components and tokens:
  after `DESIGN.md` is initialized, iterated pages that keep reusing the same
  component can be distilled into a propose-only promotion proposal, and a
  user-approved candidate is merged incrementally into the baseline.
  - `component-distill` skill + `/design-playbook:component-distill` command —
    cross-run, report-only; derives recurring-component candidates
    (`reuse`/`extend` across ≥3 runs and ≥2 scenes) and renders a proposal with
    per-candidate provenance and a user decision slot. Never writes DESIGN.md.
  - `design_baseline.py promote` — the sole durable write path (ADR-0012);
    merges a user-accepted component into `## Component Stylings` or a token
    into `## Design Tokens (Promoted)`, byte-preserving the rest, with backup +
    provenance + verify. User-gated via the promotion governance log.
  - Promotion governance events (`promotion_candidate_opened` agent-recordable,
    `promotion_decided` user-only) — append-only, `kind: component|token`.

## Notes

- Propose-only / user-gated: no automatic promotion, no agent self-promotion
  (roadmap L121/L260). The durable DESIGN.md write stays in `design_baseline.py`.
- New command → minor version bump (ADR-0015 stable main); `COMMAND_INVENTORY`
  gains the 0.25 surface.

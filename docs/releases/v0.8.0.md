# v0.8.0 - Preview control resources, adaptive theming, and validation hardening

**Tag:** v0.8.0 · **Previous:** v0.7.0 · **Date:** 2026-07-31

## Summary

Minor release for the Preview control surface and its release guards. The
embedded control document is now assembled from separately testable HTML, CSS,
and JavaScript resources; the UI follows both the operating-system theme and
host theme changes; and the G5 confirmation path rejects aborted records and
stale rejected responses more reliably. Validation tests now keep prose gates,
stage artifacts, and generated Preview markup in lockstep.

No command, skill, or manifest schema changes are included.

## Changes

### feat(preview): split control resources and sync theme

- Extracted `mcp/preview/control.html`, `control.css`, and `control.js` from the
  Python module. `control.py` now caches and assembles those package resources.
- Added adaptive light/dark styling for system preference and host
  `data-theme` / class changes, including floating annotations.
- Raised the light-theme primary action contrast to 5.47:1.
- Added raw-resource, assembled-resource, JavaScript syntax, live-theme, and
  computed-style regression coverage.

### fix(preview): harden the G5 confirmation path

- Shared `is_confirmed_valid` validation rejects confirmation records marked
  `aborted: true` instead of allowing them to satisfy G5.
- A rejected or delayed POST can no longer overwrite a later valid confirmation
  result in the Preview control UI.
- Removed obsolete confirmation writers from `confirm.py` after consolidating
  the active path.

### refactor(validate): enforce lockstep release contracts

- Named required prose phrases and anchored failures to the relevant gate.
- Added a non-vacuous `ROUND_HTML` lockstep check so generated Preview markup
  cannot silently drift from validation expectations.
- Added a repository-level test that keeps `STAGES.md` artifact markers aligned
  with the regular expressions in `validate_run.py`.
- `scripts/validate.py` now requires all three Preview control resources in the
  published package.

## Known limitations

- Browser-backed Preview checks still require Playwright and Chromium.
- Host-driven theme synchronization recognizes the supported `data-theme` and
  theme-class conventions; custom host theme signals require an adapter.

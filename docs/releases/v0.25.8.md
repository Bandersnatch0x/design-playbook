# v0.25.8

Release prepared 2026-11-08. A minimal-increment release, not a
no-behaviour-change one: the default acceptance mode is now fail-closed, and
that migration is the largest thing a reader of these notes has to act on.
No command, skill, or MCP server is added or removed.

## Complete acceptance is the default

- A bare `validate_run.py` invocation now runs complete acceptance, the same
  gate `--strict` selects. Preview, evidence, coverage, and a valid run
  profile are required; a missing one is a failure, not a skipped check.
- Historical structural-only runs keep working through an explicit
  `--legacy`. A selective `--require-*` invocation keeps exactly the scope it
  names. Neither is complete audit acceptance, and neither is reported as
  such.
- Complete acceptance requires the run-profile block from one deterministic
  plan location — `<run-root>/plan.md` when `--run-root` is given, otherwise
  the report's own directory. There is no cwd, spec-dir, or ancestor
  fallback, so a profile cannot be satisfied by a file that happened to be
  nearby.

## Repair proof and captured-byte integrity

- A blocking finding that a closure claims to repair must name its criteria
  (`criteria: L6.<n>`); a closure with no criteria, an unknown criterion, or
  a duplicate fails closed, and the closure must resolve to that finding
  alone.
- **Visible-state (screenshot) repairs** need one named pair per closure and
  criterion:

  ```text
  repair-evidence: criterion=L6.3 before=evidence/L6.3-empty-r1.png after=evidence/L6.3-empty-r2.png
  ```

  `before` must be the finding's own `evidence:` artifact and `after` the
  artifact the criterion's current ledger row observes. Both halves bind
  through `evidence/manifest.jsonl` to the same criterion and the same
  complete viewport; each half declares the SHA-256 of its own captured
  bytes, and the two digests must differ, because byte-identical visual
  halves are insufficient to show the declared visible change.
- **Nonvisual evidence types** (`a11y_tree`, `interaction_trace`,
  `automated_check`, `declaration_coverage`) retest in their declared type.
  An explicitly written pair is still validated, but its absence creates no
  visual obligation, and identical bytes are legal for them.
- Changed bytes never establish criterion success on their own; the
  criterion's current ledger result must pass.
- Declared artifact digests must match captured bytes, and the manifest and
  its artifacts must come from the same explicit run authority. Console
  freshness compares two captures instead of substituting later filesystem
  bytes.
- A present design baseline is verified against the explicitly authorized
  project and run from captured owner findings. A genuinely absent baseline
  stays optional.
- `design-baseline findings` projects the existing checks into seven stable
  finding codes over `{severity, path, code, message}`, so a downstream gate
  can cite a baseline finding; `verify` keeps its original result, and what
  cannot be judged stays an explicit advisory rather than a pass.

## Declarations that are now judged

- Two artifacts were declared and read by nothing. `reference/contract.md`
  now has G13, which checks its own template axes; a decision report's
  verbatim top block is checked by G10 whenever the report exists.
- Rendered design-token probes read computed type steps, palette membership,
  and the inner/outer radius relation against the declared bundle. Each axis
  that cannot be measured is named as undecidable with its reason, and an
  empty finding list does not prove conformance while any axis is
  undecidable.

## Review isolation

- `ui-evaluator` runs as a read-only fork over an explicit artifact set. The
  parent preserves the returned report and refuses an incomplete one.
  Producer conversation, plan notes, and self-assessment are not inputs, so a
  claim that cannot be re-derived from a bound artifact is `blocked`.
- This is conversation isolation, not an operating-system filesystem
  sandbox; the tool trace remains the evidence, and the skill says so.
- `ui-picker` enumerates empty, loading, error, permission, and dense states
  as candidate rows instead of leaving them to be remembered.

## Installation and distribution

- `init` now generates a skills tree for the seven non-native Tier 1–2 rows
  at each row's declared project-relative landing point. Tier 3 remains the
  shared `AGENTS.md` floor. Landing points are matrix declarations, not live
  host discovery.
- Portable `plugin.json` and `mcp.json` manifests are generated from the
  matrix, packaged, and checked for drift and pack contents.
- Adapter rows carry lifecycle status (`active`, `deprecated`, `rebranded`,
  `dead`) and a successor where one exists. A dead product's adapter is no
  longer emitted.
- Both stdio tool declarations carry an `outputSchema` and behaviour
  annotations; the preview tool's input schema sets
  `additionalProperties: false`; `.mcp.json` declares `type` and `$schema`.
  The evidence manifest has a v1 JSON Schema with a zero-dependency validator,
  and a registered capture-provider interface. `mcp/version.py` reads
  `.claude-plugin/plugin.json`, so the adapters cannot report a version they
  are not.

## Registry, hooks, and workbench

- Machine-detector rules resolve to real callables — contrast, hit target,
  and text size — each failing closed on a malformed capture.
- A nonblocking post-edit hook runs the source-decidable CSS contrast subset
  only. It does not claim that rendered checks ran during editing.
- Registry entries load through one ordered shard index. The split is
  organizational; no total token saving is claimed.
- A propose-only agent can read its request counter through
  `?fields=counter` without the `read-context` grant, so it can claim and
  report; every write still sends `expectedCounter`, so a stale counter stays
  a conflict. A stale canvas list response can no longer clear a newer
  render.
- The local AOCI cognition layer is untracked, so a clone no longer carries a
  half-usable index.

## Known limitations

- Live third-party host discovery is not performed; skill landing paths
  follow the matrix declaration.
- Example evidence under `examples/` is synthetic and labelled as such; it
  is not a real capture.
- The client route derivation for the workbench web app (`web/app.js`) stays
  out of scope (ADR-0048).

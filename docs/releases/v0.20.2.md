# v0.20.2 - Architecture seams and release verification

Patch release prepared 2026-08-16.

Deepens shared run facts, release verification, showcase state, and install
inventory without changing public Design I/O declarations or command inventory.

## Run facts and validation

- Makes `RunFacts` one immutable snapshot for plan, point-back, run-profile,
  decision-report, shaping, baseline, craft-guard, and declared Fill facts.
- Removes duplicate run-root artifact reads from run status and validation while
  keeping gate policy and status narration in their existing owners.
- Fails closed on unreadable non-missing run artifacts and keeps unsupported
  run-profile versions rejected by both production validation and standalone G8.
- Marks the synthetic user-test notes as non-evidence; the complete export-entry
  fixture now validates without a human-subject quarantine warning.

## Release transaction

- Centralizes npm registry hit/E404 classification in
  `scripts/release_transaction.py`; both release workflows use the same CLI
  adapter instead of duplicating shell policy.
- Makes registry and provenance retry behavior deterministic under injected
  command, clock, temporary-directory, and cleanup adapters.
- Preserves stable-main, gate-then-merge, recovery ancestry, bounded retries,
  provenance checks, and atomic release identity.

## Showcase and install inventory

- Completes queue-monitor state extraction: selection, scope, and retry targets
  come from `queue-monitor-state.js`; HTML remains the DOM/timer adapter.
- Adds root-only normalized package inventory facts for source, installed plugin,
  and npm-unpacked surfaces, including exact MCP entrypoint comparison.
- Keeps the new inventory helper outside the published package while clean
  consumer tests continue to verify bundled RunFacts, Preview, and Evidence.

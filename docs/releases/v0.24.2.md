# v0.24.2

Patch release prepared 2026-09-19. It registers the state-completeness
rule family, fixes a connection-teardown defect in the bundled Run Console
server, and adds a report-only context budget tool for the skill surface.

## State-completeness rule family

Three advisory protocol-check rules enter the first-party registry in
first-party wording, closing a review blind spot that community tooling
for coding agents keeps patching by hand:

- **STATE-01 Pending feedback.** Asynchronous triggers and data-loading
  regions present pending feedback that names the operation; a silent
  trigger or a bare anonymous spinner is a finding.
- **STATE-02 Zero-data presentation.** Data-fed collections declare what
  first-load-empty and filtered-empty look like, with a next action; blank
  regions that force users to guess are a finding.
- **STATE-03 Failure feedback.** Failed asynchronous paths present
  recoverable feedback naming what failed and the next action, instead of
  failing silently to the console or surfacing raw traces.

All three enter advisory with three-state applicability predicates,
rendered+source evidence layers, and S2/fact severity (declared-coverage
class). The registry split rule is interpreted by capability-domain group
(all 23 entries live in D4). A review exercise on a real dogfood artifact
produced two hits and one justified not-applicable, recorded as evidence.
The craft-guard reference layer no longer enumerates registry entries —
the registry is the single authority (its old enumeration had drifted).

## Run Console connection teardown

A client body left unread in the receive buffer (a POST whose
Content-Length is absent) made a plain connection close emit a TCP reset
on Windows, so the client got a connection-abort error mid-read instead of
the response that had already been sent — the root cause of intermittent
test failures across three prior runs. The request handler now flushes the
response, half-closes, drains the peer's remaining bytes, then closes;
teardown is never a reset and response bytes are unchanged.

## Context budget report

`scripts/context_budget.py` reports the context weight of the skill
surface: the always-loaded SKILL.md face per skill, its on-demand
references, the worst-case full-pipeline total, and the heaviest files.
Token counts are character-level estimates (ascii/4 + non-ascii), explicitly
labeled; the tool is purely informational — no thresholds, no gates, no
writes, no network. The report recorded at release time is the context
baseline for future skill-surface changes.

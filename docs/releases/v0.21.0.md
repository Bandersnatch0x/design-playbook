# v0.21.0 - Headless scenarios, Run Console v1, and routing

Draft prepared 2026-08-27. Release transaction pending: version sites,
badges, and npm promotion are bumped by the transaction, and promotion
waits for the first green nightly host-scenario run.

Minor release: 44 commits since v0.20.2 carrying user-facing capability
(adaptive routing, audit preferences, preview upgrades, host scenarios)
plus engine hardening. No change to the install surface or command
inventory.

## Adaptive routing and durable reference inputs (ADR-0032, #80)

- Route every run through the packaged router: entry conditions
  (`requires_reference_contract`, baseline need) come from one routing
  module, and skill prose consumes the router flags instead of restating
  the route table.
- Durable reference intake: screenshot/URL/analogy inputs land as
  inventoried assets with a manifest; url/analogy ingest without a
  contract is rejected, and write errors fail closed.
- A manifest write failure no longer strands orphaned reference assets:
  the fresh asset is rolled back before the error propagates (#74
  fail-closed follow-up).
- No-vision hosts request written context instead of silently guessing
  at screenshot content (#82).

## User-selectable audit preferences (ADR-0033, #81)

- `craft-guard`, `observe*`, and `ui-evaluator` become user-selectable
  audit stages: the pipeline asks once on first run and records the
  choice in `.design-playbook/preferences.yaml` (version-controlled;
  per-machine overrides in `preferences.local.yaml`, gitignored).
- Skipping `ui-evaluator` still produces the point-back skeleton marked
  `audited: false`; strict validation rejects both unaudited and
  ambiguous audit markers, so optionality never becomes a forgery
  channel.
- Preference-file boundaries are hardened on Windows: UTF-8 BOM reads,
  CRLF round-trips, and trailing-space duplicates no longer corrupt the
  team layer.

## Preview upgrades (#83, #84, ADR-0034)

- Draw mode: freehand stroke anchors on the prototype.
- Drawer redesign with a compliant skip disposition (ADR-0008): skip
  labels are disjoint from confirm labels, and the restored pin row,
  abort flow, draft, and in-drawer revise options return.

  overhaul handoff.
- Pin annotations stay in sync: removal and undo now clear the
  cross-origin highlights and badges (E2E S12-S14, in CI next to the
  frontend floor gate).
- Stage 9 static handoff is decoupled from the review session, and the
  minimum static handoff reference delivery is specified (#84, #36).

## Headless host scenarios (#49-#51, #94-#98)

- Pack-driven host-scenario runner (`scripts/host_scenario.py`): one
  recorded scenario per slice — prompt, seeded declaration inputs,
  expected/forbidden artifacts, validator contract, run-status stage
  obligations, timeout, isolation spec.
- `ux-spec-slice` (#49): an isolated temp target plus a local
  `--plugin-dir` load, one fixed ops-inbox ask driven through `ux-spec`
  only via headless `claude -p`, judged by validate_run G1 on the
  produced spec. No Fill, no preview confirm.
- `ui-picker-slice` (#50): the packaged dogfood spec is seeded as the
  only declaration input and must stay byte-identical; the emitted
  decision report is judged by G10 through `--decision-report`.
- Nightly CI workflow (#51) runs the scenarios on a 75-minute budget;
  skip-not-silent-green on missing host binary or credentials. Local
  real-credential verification raised the ux-spec slice timeout to
  2400s and unblocked headless claude runs.

## Run Console v1 (RCV1-001..012 + R1)

- The read-only Run Console chain is complete: frozen Snapshot v1
  contract, source-bound snapshot builder with read parity, loopback
  single-run read API, console UI, typed next-action and safe metadata
  seams, typed action allowlist, Hallmark theme with bilingual i18n,
  and point-back evaluation / specification intent projection seams.
- RCV1-R1 legibility remediation shipped after the first trial miss;

  One owner per authority read (ADR-0039) landed underneath the chain.

## Engine architecture (2026-08 architecture survey)

- SKILL.md Steps and the `STAGES` registry are held in lockstep by
  `StageMirrorLockstepTests` (order + artifact markers); the test caught
  real drift on landing — the `reference/manifest.json` path prefix and
  the concrete `filled-ui.html` / `filled-ui.md` Fill artifact names —
  and the mirror notes now name the owner (`stages.py`) and the test.
- `validate_run.run()`'s 13-parameter interface collapsed into a frozen
  `RunInputs` value object; CLI flags, exit codes, and finding order
  unchanged (ADR-0023), both in-process callers migrated.
- `run_status.py` split into a thin CLI seam plus
  `scripts/status_projection.py` (typed NextAction model, stage / vNext
  / verdict inspectors, forward-action resolver) as a byte-identical
  move; the `scripts/run_status.py` subprocess path contract is
  unchanged.
- Host-scenario packs validate their `run_status_required_stages` keys
  against `STAGES_BY_KEY` at construction, so a renamed registry key
  fails at import, not as a nightly run-status mismatch.

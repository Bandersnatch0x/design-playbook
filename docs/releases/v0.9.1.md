# v0.9.1 — evidence run-root warning fix

Released 2026-08-03.

Patch release: fixes only, no new surface. Cut from the post-v0.9.0 fix batch
(`a3d754c`), before the v0.10 run-review work on `main`.

## Fixed

- **Evidence MCP: run-root warning narrowed.** The `DESIGN_PLAYBOOK_RUN_ROOT`
  stderr warning introduced after v0.9.0 fired on shipped defaults (root
  `.mcp.json` ships `"."`; npm/pi installs are unset) on **every capture** —
  a 100% false positive on correct usage. It now fires only when the
  cwd-relative default resolves to a directory with **no run marker**
  (`plan.md` / `point-back.md`), and only **once per process**
  (`mcp/evidence/server.py`). Covered by a new no-chromium stdio test.
- **Orchestrator skill: async-init capture timing.** Step 9.2 now instructs
  including a `wait_for_state` action when the page has an async init
  (skeleton/loading before `body[data-state]` reaches the target state) —
  a capture landing mid-init honestly records `observed_state: loading`,
  which proves the wrong criterion (found in the 2026-08-01 settings
  dogfood run).
